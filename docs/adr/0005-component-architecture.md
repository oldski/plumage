# 0005. Component architecture for @plumage/ui

- **Status:** Accepted
- **Date:** 2026-10-29
- **Scope:** Plumage

## Context

[ADR 0001](0001-build-design-system-on-shadcn.md) chose shadcn/ui as the starting point.
This ADR records how the port is structured: package shape, React patterns, how classes
stay on tokens, and where we deliberately departed from shadcn.

## Decision

**Source-only workspace package.** `@plumage/ui` exports TypeScript source
(`"exports": { ".": "./src/index.ts" }`), not a build. Storybook (Vite) and Finch (Next.js
with `transpilePackages`) compile it directly. There is no bundler config to maintain, and
the shadcn registry (step 10) ships source anyway. `styles.css` declares `@source "./"`,
so any app importing it lets Tailwind find the component classes automatically.

**React 19 patterns.** Components are plain functions typed with `ComponentProps<...>`,
which in React 19 includes `ref`, so refs forward without `forwardRef`. Radix comes from
the unified `radix-ui` package, `asChild` uses `Slot.Root`, variants use
class-variance-authority, and every part carries a `data-slot` attribute as a styling
hook, as in shadcn.

**Classes stay on tokens, enforced by tests.**

- The Tailwind theme only knows Plumage tokens ([ADR 0003](0003-token-architecture-and-theming.md)).
  One amendment found while porting: the theme keeps `--spacing-0`, because `p-0`,
  `inset-0`, and `min-w-0` are layout mechanics, not design values.
- `test/utilities.test.ts` extracts every class from the component sources with
  Tailwind's own scanner, compiles each against the theme, and fails on any that
  produce nothing (typos, `text-sm`, `p-4`). It also fails on arbitrary values holding
  literal lengths, durations, or colors; `w-[calc(100%-2*var(--pl-space-xl))]` is fine,
  `w-[320px]` is not.
- `cn()` uses tailwind-merge configured from a `tailwindMergeConfig` export generated by
  the token build, so conflicts resolve correctly (`text-muted` and `text-body` coexist;
  `shadow-modal` overrides `shadow-raised`).

**Missing values go into tokens, not components.** Porting surfaced needs the token layer
lacked. They were added to Plumage at the right tier: overlay widths (`size.overlay.*`), a
small `radius.indicator`, and component tokens for checkbox, switch, sheet, menu, toast,
dialog width, and tooltip width.

**Shared interaction utilities.** `styles.css` defines `focus-ring` (one focus treatment
everywhere, from `color.border.focus` and the focus ring tokens) and `interactive`
(translucent hover and press washes layered over any fill). Motion utilities
(`animate-pop-in`, `animate-slide-in-right`, and so on) are built from the brand's
duration and easing tokens, so reduced motion and brand personality apply automatically.

**Deliberate departures from shadcn.**

| Component       | Change                                                                            | Why                                                      |
| --------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Button          | `type="button"` by default; variants primary, secondary, ghost, destructive, link | Avoid accidental submits; names describe intent          |
| Badge           | `tone` (neutral, accent, positive, negative, warning, info, outline)              | Status is what badges carry in a data product            |
| Checkbox        | Indeterminate state                                                               | Parent rows in tables                                    |
| CardTitle       | `asChild`                                                                         | Cards can contribute a real heading to the outline       |
| Tabs            | Line indicator uses the text-safe accent                                          | 3:1 against the surface in every brand                   |
| Toast           | Sonner, unstyled, dressed in tokens; theme follows the provider                   | shadcn's own recommendation; no `next-themes` dependency |
| Overlays        | Portal into the nearest Plumage scope                                             | See [ADR 0006](0006-plumage-provider-and-scopes.md)      |
| Popover offsets | Token translate instead of pixel `sideOffset`                                     | Gap follows density                                      |
| Label           | Added to the primitive set                                                        | Every form control in the set needs one                  |

## Consequences

- **Good:** a stray raw value fails CI with the file and class named, so "no hardcoded
  values" is a checked property rather than a review comment.
- **Good:** brands and densities restyle everything, including motion, with no component
  changes.
- **Bad:** every new size a component needs is a token decision first. That is the point,
  but it slows down quick experiments.
- **Bad:** consumers must run Tailwind v4 and import the token CSS; there is no
  precompiled CSS build of the components. Revisit if a non-Tailwind consumer appears.
